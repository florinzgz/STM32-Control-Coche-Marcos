# Static Analysis Stack

## Scope

The validation stack is intentionally conservative and report-first:

- STM32 owned firmware: `Core/Inc`, hand-maintained files in `Core/Src`
- ESP32 owned firmware: `esp32/include`, `esp32/src`
- Host tests already present in `Core/Src/test_*.c` and `esp32/src/test_*.cpp`
- CI scripts and validation workflow

Out of scope by default:

- `Drivers/`
- `Middlewares/`
- STM32 startup/system/autogenerated support files
- external PlatformIO packages and `.pio/`
- build outputs (`build/`, `Debug/`, `Release/`)

## Tooling Layers

### Layer A — Build / Syntax / Warnings

- STM32 CI build uses `arm-none-eabi-gcc` through `make -j2`.
- STM32 warning policy remains `-Wall -Wextra -Werror` where already clean.
- ESP32 build stays optional in CI: `pio run -e esp32s3` is attempted when PlatformIO can be installed, but a temporary tooling/network failure does not block the rest of validation.

### Layer B — Cppcheck

Run:

```bash
./scripts/run_cppcheck.sh
```

Behavior:

- report-only by default
- owned STM32 firmware, STM32 host tests, ESP32 firmware, and ESP32 host tests are analyzed in separate passes
- uses `.cppcheck-suppressions.txt`
- excludes generated/external trees from gating
- writes `artifacts/static-analysis/cppcheck.txt`

Optional strict mode:

```bash
CPPCHECK_ERROR_EXITCODE=2 ./scripts/run_cppcheck.sh
```

### Layer C — Clang-Tidy

Run:

```bash
./scripts/run_clang_tidy.sh
```

Behavior:

- uses `.clang-tidy`
- never applies fixes
- generates a local compile database for owned STM32 sources
- attempts an ESP32 compile database only when PlatformIO is available
- writes `artifacts/static-analysis/clang-tidy.txt`

### Layer D — Clang Static Analyzer / scan-build

Included in:

```bash
./scripts/run_static_analysis.sh
```

Behavior:

- runs only when `scan-build` is available
- report-only by default
- stores log plus HTML output under `artifacts/static-analysis/scan-build-html`

### Layer E — CodeQL

GitHub Actions includes an `optional-codeql` job for C/C++.

- manual build mode
- currently focused on STM32 compilation, because that is the part with a deterministic local toolchain
- non-blocking until the alert stream is stable

### Layer F — Flawfinder

Run:

```bash
flawfinder --minlevel=3 --error-level=3 Core/Src Core/Inc esp32/src esp32/include
```

- level `>= 3` remains the blocking threshold
- external trees stay excluded

### Layer G — Lizard

Run:

```bash
lizard Core/Src Core/Inc esp32/src esp32/include -l c -l cpp -T cyclomatic_complexity=15 -w
```

- threshold stays at 15
- legacy hotspots are reported, not blocked

### Layer H — Semgrep

Not enabled yet.

Reason: current C/C++ coverage is already provided by compiler warnings, cppcheck, clang-tidy, scan-build, flawfinder, and CodeQL. Semgrep is being deferred to avoid extra noise until a minimal high-signal ruleset is justified.

## Combined Runner

Run the full local stack:

```bash
./scripts/run_static_analysis.sh
```

Outputs:

- `artifacts/static-analysis/summary.txt`
- `artifacts/static-analysis/cppcheck.txt`
- `artifacts/static-analysis/clang-tidy.txt`
- `artifacts/static-analysis/flawfinder.txt`
- `artifacts/static-analysis/lizard.txt`
- `artifacts/static-analysis/scan-build.txt`

- clang-tidy

- optional CodeQL
- artifact upload and suppression documentation
